# OX Novels B9.2.8 — TEST ONLY: mutation-aware DriveApp audit

**NO deployment. NO Apps Script edits. NO Cloudflare setup.**

This small patch adds one isolated Node.js offline audit module, one regression test file, and a Windows test BAT. It does NOT change the B6.5 player streaming implementation, the working B9.1.1 Player Admin, the original .dev.vars files, the static 242 catalogs, the Google Drive resolver, or either production account.

## How to apply safely

1. Back up `C:\Users\dundi\OX-Novels-B9.2-TEST`.
2. Extract this ZIP into that TEST folder, preserving directory structure (not into the production `OX-Novels` folder).
3. From the TEST folder run `local-player-b9.2\B9.2.8-VERIFY-LOCAL.bat`.
4. Expected: **130 tests passed, 0 failed** on Node.js 22+.
5. If anything fails, stop: do not run any CONFIGURE, Wrangler, migration or deploy commands.

## Added functions

- `scanDriveAppPass`: one complete paginated traversal of a story root; rejects missing/invalid pages, stale folder binding, duplicates, cycles, invalid timestamps, missing cursors and resource ceilings.
- `auditDriveAppTwice`: runs two **independent** complete traversals with fresh iterators and compares canonical metadata. If folders, track IDs, names, MIME types, sizes, or modification times differ, reports `MUTATION_DETECTED`.
- `compareDriveAppPasses`: equality is explicitly labeled `STABLE_OBSERVED_TWICE_UNPINNED`, **never** snapshot verification.
- `offlineAuditBudget`: estimates twice the metadata reads and refuses an unsupported claim of quota safety.

## What this patch proves (local only)

- Simulated new/deleted/renamed episodes and new folders are detected between passes.
- Duplicate file IDs and folder cycles stop the audit instead of being accepted.
- Partial pages, expired cursor failures, invalid MIME/size/timestamps, and unknown usage never yield publication permission.
- The real B9.2.7 experimental `.gs` source is exercised in the Node test harness; **not against live Google Drive**.
- All 242 existing catalog tests (B9.2.0 through B9.2.7) continue to pass.

## What it DOES NOT prove

**Crucial:** Google Drive's `DriveApp` continuation tokens resume iteration but do not guarantee immutable snapshots. Two complete identical passes improve change detection but cannot rule out all races, omissions during concurrent updates, or ABA mutations between observations. Consequently, even when two passes agree: `stableSnapshot=false`, `canStage=false`, `canPublish=false`, `productionApproved=false`.

The original B9.2.5 pinned-snapshot contract must NOT be bypassed or weakened to accept this observation-only result.

Other unsolved work:
- Real Google Drive Changes API token-based change verification or another sound consistency strategy; permission/scoping and false-negative analysis required.
- Integration of a resumable drive pagination scheduler into a real remote Worker.
- Cloudflare D1 SQL semantics, Worker 10 ms CPU, Apps Script quotas, backoff and rate limits tested under genuine staging (not production).
- Verified changed-only full staging and **atomic** KV catalog publication.
- Scan history, Admin alerts, control-plane authentication and emergency revert.
