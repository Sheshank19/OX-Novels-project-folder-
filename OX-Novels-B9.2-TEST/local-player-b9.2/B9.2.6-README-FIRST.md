## What changed

- `b924-compact-checkpoints.js` now optionally accepts `fence` for page and seal writes. The `fence` assertion, page/folder/scan updates, and assertion cleanup run in **one atomic database batch**. The SQLite trigger fails the transaction if the lease was stolen or expired. Legacy *offline* direct functions are still callable without fencing for older mock tests; production cannot safely rely on those.
- `b925-durable-scheduler.js` supplies current job lease token + epoch to both write paths. It optionally accepts a fresh `commitClock` for deterministic tests; a real Worker must supply a trusted current clock at commit time. Retry handling now uses the actual simulated commit time when rejecting an expired lease. Its D1-write estimate accounts for the extra transient assertion insert/delete per step, but remains an **underestimate** of real writes.
- `0004_b926_FENCING_LOCAL_ONLY.sql` defines the offline guard table and assertion trigger. **Never run this migration on remote D1.** The schema is a design prototype and is not a production migration.
- `b925.test.mjs` references the new offline migration so the old 19 tests continue to work with the upgraded scheduler.
- `b926.test.mjs` adds **15 tests** for stolen/expired/forged tokens, mid-batch takeover, rollback when later SQL fails, continuation across pages, unchanged-story sealing, and quota safeguards.

## Important limitations

1. **Actual Google Apps Script Drive resolver source is not included in the original uploaded project.** Existing `mode:list_children` calls are not sufficient to prove stable pagination, snapshot immutability, or a trustworthy final revision proof. Our mocked begin/page/end remains a contractual simulation only.
2. **Not tested against live Cloudflare D1 transaction semantics, Workers Free 10 ms CPU, actual subrequest limits, or account-wide quotas.** Cloudflare documents D1 `batch()` atomic rollback, but live compatibility must be measured later on an isolated, approved staging environment.
3. **No dispatcher, nightly automatic scan, complete changed-story staging, KV publication, or admin alerts** are wired into production. The static 242 catalogs and B6.5 audio streaming remain the stable baseline.
4. The fence's timestamp is controlled by the caller in this offline test. A real Worker must sample trusted time immediately before the transaction; callers must not use old request-start timestamps or browser-controlled values.
5. Fencing adds extra D1 writes. Full Free-plan viability remains unknown; the existing workload estimator intentionally does not grant deployment approval.
6. The `b925` claim and ACK operations are still separate from the page batch. The current prototype protects committed page/phase changes against a reclaimed lease. Cloud staging still needs transactional/operational tests, especially failure after page commit but before ACK.

**After this patch passes:** the next material dependency is a **redacted copy of the actual Apps Script resolver source code**, not its secret or deployment URL, so that real Drive pagination and end-to-end consistency checks can be designed and tested locally. Do not paste secrets into ChatGPT.
