## What this patch does

- `collectDriveChanges(readPage, config)` validates and exhausts a **simulated** `changes.list` pagination stream from a trusted starting token. It requires terminal `newStartPageToken`, protects against missing/cyclic pages and invalid/unknown changes.
- `classifyDriveChanges(feed, owners)` maps file/folder change IDs to already-known story IDs. Newly added files can be linked via a known parent folder. Unknown/deleted files with unknown ownership force **conservative all-story scanning**, rather than being ignored. It doesn't log raw Drive IDs.
- `planNightlyStoryOrder` never skips any of the 242 stories. It only prioritizes stories whose IDs are known to be affected. All readiness/activation flags remain false.
- Fail-closed tests for missing pages, stale identities, duplicate stories, unknown changes, removed files, cross-story moves, budget exhaustion, and attempted unsafe promotion.

## Important distinction

Google Drive's Changes API can help determine where to investigate. Its `getStartPageToken` and `changes.list` are **not the same as an immutable snapshot** of paginated DriveApp listings. Coverage also depends on the actual **resolver account**, permissions, files shared to that account, shared-drive scope, and whether all relevant file and parent changes are observable. The remote authentication and scope model remain **unverified**.

This library is **NOT connected** to Google Drive. It includes no real API calls, no script settings, no secrets, no keys, and no production deployment code. Although it illustrates a one-full-pass-plus-feed estimate, the second pass may still be required. It is **not** an approved shortcut to skip any story or authorize production catalog replacement.

### Request planning example, not a measured cost

The local 242-story manifest contains **4,978 metadata page commitments**. Two complete comparable passes would be **9,956 page reads** (assuming unchanged pagination). A hypothetical one pass plus a one-page change feed would be **4,979 requests**. Those are *illustrative* workloads, not measurements and not a guarantee that one-pass validation is safe.
